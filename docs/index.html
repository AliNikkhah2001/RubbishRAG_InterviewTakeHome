Story

You are given a Persian RAG chatbot over a real credit-scoring knowledge base (330 QA pairs in corpus/test.csv). It looks finished — but it only scores ~40% on the visible benchmark. Your manager says: "AI built this in one minute — prove it wrong." Find the bugs, measure them with logged probes and plots, and fix them. You can use any AI tools, but the bugs exist only inside this specific black box — generic advice won't work.

What you need to do

  1. Fork the repo on GitHub.
  2. Check out the candidate branch (sealed bytecode, encrypted evaluation).
  3. Create a branch: solution/<your-github-username>
  4. Python 3.11 is required (the sealed bytecode is compiled for 3.11).
  5. pip install -r requirements.txt
  6. python3 rubbish.py salam — first run asks for your name/email/GitHub
  7. python3 rubbish.py bepar "رتبه C1 یعنی چی؟" --topk 5 — probe the black box
  8. python3 rubbish.py bench — run the 20-question visible benchmark
  9. python3 rubbish.py bekesh — generate diagnostic plots
  10. python3 rubbish.py bastesh — stamp your report card + pack submission.zip

Architecture (what you are working with)

corpus/test.csv → chunk (300-char slices) → POST /retrieve → hits {bm25,dense,fused}
→ rerank (shared-word count) → resolve (always answers, never clarifies)

The pipeline is four stages, each a Python decorator in rubbish_rag/pipeline.py:

  • @chunker — splits documents into 300-char pieces (loses headers)
  • @retriever — forwards the query to the black box, returns scores per hit
  • @reranker — orders hits by word overlap with the query
  • @resolver — always returns an answer, never a clarifying question

You can override any stage by re-registering with the same decorator (see docs/DECORATORS_FA.md). The black box itself is sealed — you probe it, not read it.

What's in the black box? (the API server)

The POST /retrieve endpoint is a flawed hybrid search engine running locally on your machine via compiled bytecode (server/*.pyc). It combines BM25 and overlap-based dense scores — the exact fusion formula is one of the bugs you need to discover. You do not need to host any server — everything runs offline. The scoring logic and hidden evaluation queries are encrypted and never visible to you.

(Interviewers may optionally deploy this on a VPS like Vast.ai for remote testing — if so, they will give you a URL and API key. You will set it with --key or rubbish.py --key.)

Symptoms to investigate (starting points)

  • Some top-ranked hits look irrelevant — why do they score highly?
  • Queries that differ by one word get the same answer. When is that correct, and when is it a merge of two different truths?
  • Some queries have no good answer in the corpus — what does the resolver currently do, and what should a production system do?
  • The bm25, dense, and fused scores are returned per hit. Plot them before theorizing (bekesh generates three starter plots).
  • Focus on the output contract and the evaluation rubric — think about what a scorer checks.

Important signal: slots

In this corpus, a single swapped word can flip the correct answer:

  • Bank (ملی, صادرات, تجارت, …)
  • Rank code (A1 through E3)
  • Persona (حقیقی / حقوقی — these have very different numbers)
  • Amounts and time (۲۵۰, ۵ سال, ۲۴ ساعت, …)
  • Debt type (تسهیلاتی, مالیاتی, چک, محکومیت)

The black box does not handle these for you — that is your job.

Output contract (auto-graded)

{"status": "answer",  "brief": "one-line answer", "cites": [doc_id, ...]}
{"status": "clarify", "question": "مشخص کنید؟",  "options": ["گزینه۱", "گزینه۲"]}

Deliverables

  1. Fixed code: rubbish_rag/pipeline.py + normalize_fa.py + slots.py
  2. docs/PROOF.md — one section per change: symptom → probe + trace IDs → plot → decision
  3. submissions/submission.zip from rubbish bastesh
  4. Push your solution/<username> branch and/or submit the zip

Hidden evaluation (~170 held-out queries) measures accuracy, clarification behavior, and citation faithfulness. Bar: accuracy >65%, clarify >50%, plus a 30-min defense of your traces.
