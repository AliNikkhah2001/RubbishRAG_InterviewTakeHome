How RubbishRAG currently processes queries, how the black-box scorer operates, and where the algorithmic failure modes originate.

Core Pipeline Stages

The candidate codebase is divided into four decorator-managed stages in rubbish_rag/pipeline.py:

Stage Decorator Current Naive Implementation Expected Candidate Fix
Chunker @R.chunker Fixed 300-character slices of Answer; completely drops Category, Keyword, and question context. Header-aware chunking preserving metadata ([Category | Keyword]) with sentence boundary awareness.
Retriever @R.retriever Forwards the raw query to the black box untouched with no text normalization. Persian script normalization, number unification, and dual query expansion.
Reranker @R.reranker Sorts hits strictly by raw shared-word count (len(set(q) & set(d))). Slot-aware scoring (Rank, Bank, Debt, Persona), distinctive number boosts, and poison penalty.
Resolver @R.resolver Always outputs status: answer using the top hit, even when ambiguous or contradictory. Ambiguity router: returns clarify with dynamic options when key decision slots are missing.

Scoring Mathematics in the Black Box

1. Flawed Linear Score Fusion (F1)

The black-box server combines sparse BM25 and overlap dense scores using naive min-max scaling:

fused = 0.5 * (bm25 / max(BM25)) + 0.5 * (dense / max(Dense))

Why this fails: BM25 and dense scores follow completely different probability distributions. A single extreme outlier score compresses the entire score space, causing lower-ranked hits to cluster artificially. The fix: Candidates should implement Reciprocal Rank Fusion (RRF) client-side: 

RRF_score(d) = Σ [ 1 / (60 + rank_m(d)) ]

2. Aggressive BM25 Document Length Penalty (F2)

The BM25 formula in the server is parameterized with $k_1 = 1.2$ and $b = 0.9$:

denom = f + k1 * (1 - b + b * (doc_len / avgdl))

Because $b = 0.9$ is excessively high without a BM25+ floor, thorough answers that explain credit rules in detail are severely penalized compared to short fragments.

Observed Failure Modes & Investigation Areas

1. Linear Fusion Distortion

Min-max normalization can distort relative ranks in the presence of outliers. Investigate rank-based fusion (RRF).

2. BM25 Length Bias

High length penalty ($b=0.9$) penalizes long informative answers. Analyze with length-binned diagnostic plots.

3. Adversarial / Noise Documents

Unverified keyword-stuffed documents exist in the index (doc IDs ≥ 9000). Ensure your pipeline filters or demotes them.

4. Persian Script Variations

Digits (۲۵۰ vs 250), Arabic characters (ي/ك/ة), and colloquial forms (میشه vs می‌شود) require robust canonicalization.

5. Fragmented Chunking

Fixed 300-char slices sever numbers from units and discard category headers. Design metadata-aware chunks.

6. Bag-of-Words Reranker Trap

Simple token overlap favors repetitive keyword spam over precise credit entities. Implement entity-aware scoring.

7. Ambiguity Resolution Gating

Queries missing required decision entities should trigger the clarification contract rather than hallucinating answers.

8. Polarity & Negation Sensitivity

Negation particles (نمی‌شود vs می‌شود) are ignored by bag-of-words counters, leading to opposite conclusions.

9. Context Redundancy

Redundant chunks from the same document crowd top-k retrieval. Implement deduplication to broaden evidence.

10. Fact Verification & Grounding

Subtle metric discrepancies between candidates and reference facts require grounding against corpus/test.csv.
